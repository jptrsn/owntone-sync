# Phase and fix reports

Historical records of what individual sessions did and observed, written to the
template in `../verification-protocol.md` §6.

**These are evidence, not guidance.** They describe the state of the code at the
moment they were written, and several describe defects that have since been
fixed or conclusions that were later corrected. Do not derive rules from them.

Anything a report established that still matters was promoted into
`../invariants.md`. If a report seems to imply a constraint, check there instead.

Kept because they are the verification trail: what was actually checked, on what
device, with what evidence — including the honest NOT VERIFIED and UNKNOWN
sections, which are often the most useful part.
